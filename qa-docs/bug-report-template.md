# Шаблон баг-репорта

## 1. Название (summary)
Краткое описание ошибки по схеме: *Что? Где? При каких условиях?*

## 2. Серьёзность (Severity)
Степень влияния на систему (S1–S5), согласно определённым уровням.

## 3. Приоритет (Priority)
Очерёдность исправления (P0–P3), основанная на бизнес-требованиях.

## 4. Окружение (Environment)
- ОС
- Версия ОС
- Характеристики устройства

## 5. Предусловия (Preconditions)
Что должно быть сделано перед началом теста.

## 6. Шаги воспроизведения (Steps to Reproduce)
Пошаговый алгоритм действий.

## 7. Ожидаемый результат (Expected Result)
Как система должна была сработать по ТЗ.

## 8. Фактический результат (Actual Result)
Что произошло на самом деле.

## 9. Вложения (Attachments)
- Скриншоты
- Логи запросов к бэкенду или API нейросети
- Видеозапись экрана
